# Requirements ledger — every request the user has made

The master checklist. **One row per requirement, never deleted.** What the
product should be is explained in [docs/product-spec.md](docs/product-spec.md);
this file says whether it is. Ids are stable — commits, tests and trackers
cite them (`VEH-06`, `SEAT-01`).

**Enforced:** `test/requirements-ledger.test.ts` (in `bun run test`, so CI)
fails when a row is malformed, an id repeats, a `DONE-*` row names no guard,
or a guard points at a test file or test name that no longer exists.
`bun scripts/requirements-ledger.ts --open` lists everything not done.

## Rules for every agent

1. **A new request becomes a row in the same turn.** Use the next free number
   in its area, quote the user's words briefly, and set status `OPEN`. If the
   user repeats an existing request or reports it broken again, append the
   date to the row's gap cell (repeats signal a regression), and set
   `REGRESSED` if it had been done.
2. **Status means evidence, not intent.**
   - `DONE-DEVICE`: confirmed where the user plays (the phone for Bedrock;
     live or rendered and looked at for the web).
   - `DONE-OFFLINE`: implemented and guarded, but not yet confirmed there.
   - `PARTIAL`, `OPEN`, `REGRESSED`, `WONTFIX`: `WONTFIX` only with the
     user's decision cited in the gap cell.
   - A later change to the mechanism demotes `DONE-DEVICE` to
     `DONE-OFFLINE` until the next device round.
3. **Every fix adds a guard.** A test that would fail if the requirement broke
   again, named in the guards cell as `test/<file>.test.ts :: <test name
   substring>`. Other guard forms:
   - `sim:<regression or scenario id>`;
   - `gate:<script>` (a manual gate, not in CI);
   - `rule:<file>` (process rules);
   - ` (corpus)` marks a guard that is skipped without the local corpus or
     packs, so it does not protect anything on CI.
4. **Device rounds update the device cell** with the date and round, and the
   result in the user's terms.
5. **Never delete or renumber a row.** Mark it `WONTFIX` and say why.
